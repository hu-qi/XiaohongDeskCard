# 产品需求文档 · XiaohongDeskCard MVP

状态：草案 v0.1（2026-11-18） · 硬件未实测

## 1. 定位

基于小鸿 AI WS63 原装 240×240 TFT 的微型智能桌牌。首版的核心价值不是会议系统，而是**同一张桌牌通过 BLE / SLE / Wi-Fi 三种链路修改，并能在 HarmonyOS App 中自动选择可用链路**。

## 2. 范围（P0）

| 模块 | P0 要求 | 验收 |
|---|---|---|
| 显示 | LVGL 显示姓名、职位、组织、模板 | 中文不乱码；长文本有可预期截断/缩放 |
| 配置 | 保存最新成功提交的桌牌内容 | 断电重启恢复；存储失败可提示 |
| BLE | WS63 GATT Peripheral/Server | 手机发现、绑定、写入、收到业务 ACK |
| SLE | WS63 SSAP Server | 星闪客户端发现、连接、写入、收到业务 ACK |
| Wi-Fi | WS63 作为 STA 接收 HTTP | 同局域网发送命令，收到业务 ACK |
| App | ArkTS 编辑/预览、设备发现与能力提示 | 每种已验证传输通道可完成同一操作 |
| 安全 | 配对/认领、写入权限、输入边界验证 | 未授权写入被拒绝 |
| 诊断 | 设备 ID、固件版本、连接类型、最后更新结果 | 串口可追踪单次请求 |

## 3. 不纳入首版

外接电子纸、双面异显、云端账号、会议座次批量编排、AI 模板、微信小程序直连星闪、多台设备并发、OTA。为它们预留接口，但不以其为首版交付门槛。

## 4. 核心用户流程

1. 启动设备，原装屏显示初始桌牌和配对状态。
2. HarmonyOS App 查询本机 BLE/星闪能力，发现桌牌，完成认领与授权。
3. 编辑姓名、职位、组织，选模板并预览。
4. 选择 **自动 / BLE / 星闪 / Wi-Fi** 发送。
5. App 显示“发送中 → 已接收 → 已显示 / 失败”，设备更新 LVGL 并持久化。
6. 断电重启恢复最后已确认的内容。

## 5. 链路策略

- **BLE**：通用近场基线，可覆盖不支持 NearLink 的手机。
- **SLE**：HarmonyOS 原生差异化能力。需要手机支持星闪硬件与近场接口，先做支持查询，不保证所有设备可用。
- **Wi-Fi**：HTTP 控制、自动化脚本与未来后台接入。
- **Auto**：由用户可配置优先策略；默认优先已配对且可用的 SLE，再回退 BLE，再回退已认证的 Wi-Fi；是否可并发由硬件测试确定。
- **传输能力和支持矩阵**：功能可见不代表可用，前端要显示“不支持 / 未授权 / 未连接”。

## 6. 验收测试（基础）

- 3 个传输通道分别完成中文桌牌更新；有端到端日志、结果 ACK。
- 错误 JSON、超长字段、未授权访问和损坏分片不会改变屏幕。
- 网络中断、连接异常、重复请求可恢复。
- 最后成功应用的配置在重启后恢复。
- 设备不出现 LVGL 多线程调用竞态。

## 7. 待确认的硬件前提

- 小鸿所用 OpenHarmony/WS63 SDK 的 BLE GATT Server 代码与编译参数。
- 小鸿 SLE UART 例程能否复用为 SSAP 桌牌服务。
- 实际 HarmonyOS 测试手机的机型、系统版本、NearLink API 支持情况。
- 三模收发时射频共存、RAM 占用、连接稳定性。
- 原机固件项目目录、LVGL 版本、NVS/NV 持久化接口。
